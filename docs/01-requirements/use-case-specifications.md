# Спецификация детальных Use Case

## UC-01. Создание бронирования

**Актор:** ROLE_USER.

**Предусловия:** пользователь аутентифицирован; комната существует.

**Основной поток:**
1. Пользователь выбирает комнату.
2. Указывает дату и интервал.
3. Клиент отправляет запрос на `/api/bookings`.
4. Система валидирует интервал.
5. Mediator проверяет отсутствие пересечения активных бронирований.
6. Система сохраняет Booking и возвращает `201 Created`.

**Альтернативный поток:** при пересечении возвращается ошибка конфликта.

**Постусловие:** создано активное бронирование.

## UC-02. Управление комнатой администратором

**Актор:** ROLE_ADMIN.

**Предусловия:** администратор аутентифицирован.

**Основной поток:** администратор создаёт, изменяет или удаляет комнату; backend проверяет роль и валидирует данные; результат сохраняется через Foundation.

**Постусловие:** каталог рабочих пространств обновлён.
