# Финальный этап рефакторинга

## Data Mapper — обязательный элемент

Для `MeetingRoom` создан `RoomMapper`, отделяющий JPA-сущность от REST-представления `RoomResponse`.

Схема:
`Entity -> Mapper -> DTO -> HTTP response`.

Это уменьшает связанность API-контракта с persistence-моделью.

## Identity Map

В приложении используется persistence context JPA/Hibernate. В рамках транзакции повторное обращение к одной сущности использует единый объект контекста. Это соответствует паттерну Identity Map на уровне ORM.

## Lazy Load

Связи `Booking -> User` и `Booking -> MeetingRoom` остаются `LAZY`, а запросы, которым нужны связанные данные, используют `@EntityGraph`. Это предотвращает неуправляемый LazyInitializationException и позволяет загружать необходимый граф явно.

## Query optimization

Для расписания используется запрос с условиями по `room_id`, времени начала/окончания и статусу. Для БД рекомендуется индекс по `room_id/start_at/end_at`.

## Результат

Рефакторинг отделяет модель хранения от REST-ответов, делает загрузку связанных объектов явной и сохраняет тестируемость бизнес-логики.
